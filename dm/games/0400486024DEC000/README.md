# The Legend of Zelda: Ocarina of Time (`0400486024DEC000`)

A Switch 2 game: version v131072 (the update `0400486024DEC800` over the base v65536), from a `.nup`. SDK 22.2.8 built for the Switch 2 (`sdk` names its spec `Ounce`), NVN2. Nintendo EPD's engine (sead / agl / gsys, Phive) with the RomFS layout of [Tears of the Kingdom](../0100F2C0115B6000/README.md) (`Banc`, `Chemical`, `Mals`, `RSDB`, `ActorSystem`, `Pack/*.pack.zs`). **In bring-up on Android (AYN Thor, Turnip): the title menu runs at 60 frames a second with its text, the 3D scene at about 15.**

## Survey (2026-11-05, from the `.nup`)

- `sdk` makes the same 57 SVC calls as Donkey Kong Bananza's (`insn_census.py`: the same SVC numbers), so the SDK 22 kernel surface needs nothing new. The rewrite sites are of the kinds the rewriter already handles: `main` 50,390 `x18` uses and 1,264 `mrs tpidr_el0`, no `svc`; `sdk` 441 `mrs tpidrro_el0`, 45 `mrs cntpct_el0`. `main` is 15.8 M instructions (Donkey Kong Bananza's 7.2 M).
- `main` imports 1,183 functions; 659 of them are also imported by Donkey Kong Bananza's `main` (`nso_syms.py`). The rest are SDK functions the game's own `sdk` implements, over services the host may not answer yet: `nn::async` (41), `nn::audio` input streams, `nn::nfp` (amiibo), `nn::web`, `nn::ssl`, `nn::socket`, `nn::prepo`, `nn::hid` mouse.
- Shaders: `Shader/{Model,Foliage,TerrainGround,SceneMaterial}.Product.110.product.Nin_Ounce_NVN2.bfsha.zs` (the model archive is 43 MB compressed) and `Shader/ApplicationPackage.Nin_Ounce_NVN2.release.sarc.zs`.

## Shaders (2026-11-05)

`shader_split.py` finds 42,320 shaders (compute 4,100, mesh 9, pixel 22,356, task 3, vertex 15,852). The first Vulkan library build left 93 of them out; all build now, and a sample of 547 others (516 pixel, 18 vertex, 3 compute, 2 task and the 8 triangle meshes) translates to the same SPIR-V, byte for byte, as with the translator before these changes:

- **Resolved:** 74 pixel shaders query a 2D texture's size and read its third component (TXQ's depth): the SPIR-V extracted it from a two-component vector, which `spirv-val` refuses. A component the texture type does not have is now 1, as the texture header holds it (`CodeGen/Spirv/Instructions.cs` `GenerateTextureQuerySize`).
- **Resolved:** 7 shaders use `0x3a9`, the global compare-and-swap (`ATOMG.CAS`, Mesa NAK `sm70_encode.rs`): `InstEmitAmpereMem.cs` `AAtomgCas`, Rd the old value, 32-bit only.
- **Resolved:** 10 compute shaders (an RGB to YUV conversion) use `0x243`, `F2IP.U8.F32.NTZ` (base `0x043`; the name nvdisasm gives these encodings, in CuAssembler's sm_86 tables): two floats to unsigned bytes, a to byte 1 and b to byte 0 as F2FP's a high / b low; `PRMT 0x5410` then joins two such pairs, Cb before Cr (NV12 chroma). `InstEmitAmpereAlu.cs` `AF2ip`. The foliage mesh programs use its truncating form (modifiers `0xc4`): [F2IP's rounding modes](../../../docs/reference/shaders.md#f2ips-rounding-modes).
- **Resolved:** a task program reads back its own task memory (`0x923` with the mode `0xb800` its stores use): `InstEmitAmpereMesh.cs`.
- **Resolved:** `Lib/agl/agl_resource.Nin_Ounce_NVN2.release.sarc.zs/agl_common.sharcb#BAHS@0x357f0` was not a shader: the BAHS table scan paired a compute control section with a vertex + pixel program's code, and the translator stopped on its SPH word as "Ampere instruction 0x481". `shader_split.py` now leaves such a match out with a red line. Mario Kart World's compute `078997bf631992c5` fails the same way and may be the same kind of match (not checked).
- **Resolved:** mesh program `2582bd7ea6490d33` (`Shader/ApplicationPackage.Nin_Ounce_NVN2.release.sarc.zs/AglShader.sharcb`) draws points: its control section has 1 at +0x5f where the 8 triangle meshes have 3 (and 32 vertices / 32 primitives at most), it writes one index byte a primitive at 4 + t, and the point size besides position (SPH output map byte 0x35 bit 3). Its stores put the point size in plane 0, before x y z w (a depth-scaled scalar there, the four matrix rows after it), the order of the attribute addresses (0x6c, then 0x70). `mesh_facts` gives the point size plane code 132 and marks the topology (`-4, 1`; nothing for triangles, so the other layouts are unchanged); the translator declares `PointSize`, `PrimitivePointIndicesEXT` and `OutputPoints` (`MeshShaderInfo.cs`, `SpirvMeshEntry.cs`).

- **Taken from the host's saves:** 11 compute shaders the game binds from the intro on are in no module and in nothing the split reads; with `DM_NVN_SHDUMP` the Vulkan replay saved them (the intro and the title menu stayed black without them), and the split takes them from `DM_NVN_SHDUMP_DIR` (42,331 shaders, compute 4,111). Where in the RomFS they live is not found yet. They are agl's NDVE network for movies (below), which the game no longer runs since its cut.

## First start on Android (2026-11-05, AYN Thor, Turnip on Adreno 740)

- **Resolved:** `auddmg:u` (the audio device manager the SDK 22 audio client opens at startup): served by the host, its command 0 returning a proxy session ([`hle_sf.c`](../../host/hle_sf.c)).
- **Resolved:** the gRPC event engine's wakeup descriptor (`nn::socket::EventFd`): host eventfds ([`hle_net.c`](../../host/hle_net.c)).
- **Resolved:** SIGILL at `autiasp` in `DispatchFiberContext` (`sdk+0x16d40c`): Android gives each thread its own pointer authentication keys ([Pointer authentication keys differ per thread on Android](../../../docs/reference/threads.md#pointer-authentication-keys-differ-per-thread-on-android)).
- **Resolved:** the abort at `subsdk0+0xf9bc` when the intro movie starts: its AV1 decoder ([AV1 on Android through MediaCodec](../../../docs/reference/movies.md#av1-on-android-through-mediacodec)).
- The game reaches its title menu at 60 frames a second with its sound; the picture was black (the 11 compute shaders above).
- **Cut:** the 3D scene stayed black, its sound playing. agl upscales the scene into the output target (1536x864 → 2048x1152 docked, into 1920x1080 handheld) with NDSR, three HMMA compute networks (`f8965bffbdf51d78`, `a335c1db6270c355`, `fa3033d05c0a41d6`, from `Lib/agl/…/agl_ndsr_vr*.pck`), bound from the upscale step `main+0x25aa60` (call at `main+0x25ac28`, found with `DM_NVN_PROGTRACE`). On Turnip they write NaN into every texel of the target (`DM_VK_NANSCAN` saw it only at the next render pass, the screen fade, since the target is a compute pass's storage image; `DM_VK_KEYDUMP` showed that draw's buffers and vertices sane) and cost about 87 ms of GPU a frame. The render configuration's "use NDSR" byte (+0x9c0) is set by its constructor and again by the game's graphics parameters; the cut in [`patches.py`](patches.py) makes its four reads load 0 (`main+0x2503a8`, `+0x25aad0`, `+0x534e18`, `+0x654f04`), and the scene renders (Kokiri Forest's stream, 2026-11-05). Why the networks give NaN on Vulkan (the HMMA lowering, `hmma_lds`) is open.
- **Resolved:** a crash at `AddressInfo::GetReference` (`sdk+0x249874`, null + 0x20) after about 200 s on the title menu, the same in handheld mode: the host locked SDK 20's update lock (+0x2d0) where SDK 22.2 has it at +0x2d8 ([The renderer's update lock](../../../docs/reference/audio.md#the-renderers-update-lock-update_lock)).
- **Resolved:** the abort (`Result 0xe15`, `prepo:u`) when the intro movie ends: `prepo::PlayReport::Send(Uid)` ([An async context returned through x8](../../../docs/reference/services.md#an-async-context-returned-through-x8-prepoplayreportsend)).
- **Cut:** the intro movie stayed black with its sound, at about 1 frame a second. agl's movie renderer (vtable slot +0x18, `main+0x3b63360`) runs NDVE: the 11 compute programs above (HMMA, `DM_NVN_PROGTRACE` traced every bind to `main+0x20e57e0`, called from `main+0x3b634b0`) turn the 1920x1080 Y and UV planes into a 2560x1440 `NDVE_Output`, then draw it. On Turnip they take about 533 ms of GPU a frame, and `d15370a382630d4e` runs the driver out of memory while compiling (skipped with `DM_VK_CS_SKIP`). The renderer has its own plain path, a YUV → RGB textured draw (`main+0x3b62450` → `main+0x3539360`), taken when the byte at `main+0x4e95f61` is set or there is no NDVE object; the cut in [`patches.py`](patches.py) makes the byte test always take it (`tbz` → `nop` at `main+0x3b63368`), on every target.

- **Resolved (partly):** the 3D scene's speed on the AYN Thor. Raw global memory first went through a 12-step search of the pool table inlined into every access: a pass of 184 ms of GPU a frame. A cache of the last pool brought the frame to about 74 ms (40 ms of GPU). The page table that replaced the search on Android ([Global memory at an address loaded from memory](../../../docs/reference/shaders.md#global-memory-at-an-address-loaded-from-memory)) brought it to about 65 ms (36.5 ms of GPU).
  - Vertex shader `4671e5e647fc5455` (2 draws, 87,576 indices) reads light probe data through a pointer: 58 LDG.128 a vertex, which the translator split into 253 32-bit reads with a page table lookup each. Its pass took about 20 ms, and Turnip's statistics (`DM_VK_PSTATS`) put the shader at 18,008 instructions with the page table, against 50,769 with the search.
  - Measured with `DM_VK_GPUPROF`, `DM_VK_DRAW_SKIP` and `DM_VK_XP_SCISSOR`: the pass is bound by its vertices, not its pixels. Keeping the last page looked up per invocation made it no faster (22 ms).
  - The words of one vector load now share one lookup ([Global memory at an address loaded from memory](../../../docs/reference/shaders.md#global-memory-at-an-address-loaded-from-memory)): 71 lookups, 8,002 instructions, the pass at about 9 ms, the scene at about 22 ms of GPU a frame (2026-11-06, chain `d019a639a516`). The shader still costs about 8 ms of it (`DM_VK_DRAW_SKIP`); `d47c0bf264c40ee4` (6 draws, 268,743 indices) about 2 ms.
- **Resolved:** killed by the phone's low-memory killer as soon as Link moved in his house, then at its door (2026-11-06). The frame graph places new 1440x810 targets over a 305 MiB virtual pool (flags `0x2a1`) as Link moves, and the replay gave each one memory of its own: 923 MB of GPU-written images over 660 MB of storage in the house, 2,075 MB a few seconds later, kgsl past 5 GB. Pool windows ([Render targets placed over one memory, each in an image of its own on the Vulkan replay](../../../docs/reference/rendering.md#render-targets-placed-over-one-memory-each-in-an-image-of-its-own-on-the-vulkan-replay)) hold 551 images of 2,209 MiB in 800 MiB; kgsl stays at about 4.0 GB and Link walks out into Kokiri Forest (Saria's scene at 38 frames a second, the forest at 20-21).
  - Before that: `DM_VK_TEX_LAZY` and `DM_VK_TEX_PAGEOUT` brought the save's load through ([Images filled from pool storage hold texture bytes twice on the Vulkan replay](../../../docs/reference/rendering.md#images-filled-from-pool-storage-hold-texture-bytes-twice-on-the-vulkan-replay)). Offering the game a smaller pool (`DM_APP_POOL`, 7.5 or 8.25 GB) does not work: it fails its own allocations at load; it needs its 9 GB.
  - Measured with the ctl stats' memory lines (`ctl: memory:`: scratch, upload staging in flight, the driver's heap usage, kgsl; `texture objects:`: 3,769 live, none dropped without a Finalize). In Link's house: about 2.8 GB counted by the host, 3.07 GB of Vulkan memory by the driver, 3.48 GB of kgsl.
- **Resolved:** the title menu had no text; its panels drew. The shader translator lost the corner's y in the glyph vertex shader `b19e1bdd247555ec`, so every glyph quad was flat ([Ampere deferred writes lost at a guarded last instruction](../../../docs/reference/shaders.md#ampere-deferred-writes-lost-at-a-guarded-last-instruction)). The title and Options menus show all their text at 60 frames a second (2026-11-06).
  - How the game draws text: each text box is rendered once into a texture of its own (a capture pane caches it; the glyph pages are R8 linear, filled by the CPU at `main+0x1519300`), and the frame composites that texture. So the boxes' draws happen once, and a frame's draws hold no glyphs.
  - The path was found with temporary observation gates on the panes' update, the text boxes' glyph build (`main+0xe4e0e0`) and draw (`main+0x153cd80`): every step ran. Then `DM_VK_NANSCAN_GPUDUMP` read the box textures back (empty) and counted no sample for any glyph draw, and the vertex shader run on the CPU with the draw's inputs (`DM_VK_KEYDUMP_FULL`) gave every corner the same y. The gates are gone.

## Open

- The picture on Android with the movie and NDSR cuts:
  - The mesh draws (agl's meshlets: task `efaa4fa6a80ba719` and five mesh programs, among 12) are emulated as compute, and the stream of the Great Deku Tree's clearing draws again ([NVN2 mesh draws without VK_EXT_mesh_shader](../../../docs/reference/shaders.md#nvn2-mesh-draws-without-vk_ext_mesh_shader)). Still open: the cost of ending the render pass at each of them; one run killed by the system for low memory after 2.5 s, not seen again; wrong pictures here and there.
  - Resolved (2026-11-06, chain `9d178638884a`): the white haze over the house and Kokiri Forest was the exposure, from luminance sums that stayed 0 ([Float atomics in storage memory](../../../docs/reference/shaders.md#float-atomics-in-storage-memory)); the house is dark with the window's light, the forest has its contrast, and the GPU time in the house fell from about 26 to 16 ms. Earlier notes on it, kept for the record: a white haze over the Great Deku Tree's clearing and Kokiri Forest. Skipping the fog draw (fragment shader `888c1068ac8f7043`, agl's `AglShader.sharcb`) clears it, but the HDR target after that draw holds a moderate haze (`DM_VK_NANSCAN_GPUDUMP`); the scene is very bright without it too, so the exposure is the suspect (a 128x128 to 1x1 chain of passes, not looked at yet). `DM_VK_NANSCAN` (armed for 30 s at the save's load with `DM_VK_NANSCAN_HOLD`) finds NaN from the first draws: about 5,000 NaN and 30-60 infinite texels a frame in a 480x270 R11G11B10F target (format `0x3f`, a quarter of 1080p) from the first draw of its pass, vertex / pixel shaders `e3db3f1503c9232e` / `e894c441691ca151`.
  - For 10-15 s after a save loads, the screen flickers between white and objects glowing like neon (pots, trunks, lianas), then settles; no pipeline is made meanwhile, and it was there before the memory changes. With the float atomics fixed it is still there: the exposure starts from an extreme value and takes about 15 s to settle (a large saturated area in the house, then the right picture). The NaN of the bloom downsample come only in those first seconds (none 15 s after the load, its input clean).
  - The terrain's CPU-written maps: `tex_flush_upload` and `tex_dirty_upload`, as on the Mac (black holes in the ground around the paths with leaves floating in them); added 2026-11-06, their effect not checked yet.
  - Outside: `[RED] vk: fragment shader 442da04b508b2667 writes a float output to a uint target 0: that target is not written`.
  - Missing textures (the door of Link's house, bark in shadow): with `DM_VK_TEX_LAZY` a texture ID gets its image at its first use the host sees, and shaders that read the texture pool through a handle loaded from memory (`DMSH_VK_KIND_TEX_POOL`, set 1) are never seen, so those IDs keep the null view. The Mac host found the same on this game (about 33,000 IDs registered, about 300 read through pools) and fixed it with a read bitmap: each pool read sets the ID's bit, the host folds the bitmap at each submission and makes those textures (nxnative, `docs/reference/memory.md` "Shaders report which textures they read through a pool"). Planned here: the same marks added by a SPIR-V rewrite at pipeline time (`vka_spvpatch.c`) into a bitmap bound beside the pool set, read at each submission's end into `lazy_wake`.
  - The game waits for the GPU each frame: the frame is about the GPU time plus 20 ms of CPU.
- Where the byte at `main+0x4e95f61` (the movie renderer's plain path) is set, a setting or a debug switch, is not looked at.
- The translator changes move the chain version for every game: they need `scripts/regress.py check` on a Mac before they can go upstream.

## Found on this game

General changes first needed here; each applies to every game:

- **Deferred writes kept at a guarded last instruction** (`Translator.EmitOpsAmpere`, `ShadowFixedWrites`): [Ampere deferred writes lost at a guarded last instruction](../../../docs/reference/shaders.md#ampere-deferred-writes-lost-at-a-guarded-last-instruction).
- **A probed draw read back from the GPU, with occlusion and pipeline-statistics queries** (`DM_VK_NANSCAN_GPUDUMP`, `vka_nanscan.c`) and **a draw's inputs written whole** (`DM_VK_KEYDUMP_FULL`, `vka_draw.c`): [android/TESTING.md](../../../android/TESTING.md).
- **Pointer authentication keys per thread on Android**: [Pointer authentication keys differ per thread on Android](../../../docs/reference/threads.md#pointer-authentication-keys-differ-per-thread-on-android).
- **AV1 through MediaCodec**: [AV1 on Android through MediaCodec](../../../docs/reference/movies.md#av1-on-android-through-mediacodec).
- **SDK 22.2's audio renderer update lock**: [The renderer's update lock](../../../docs/reference/audio.md#the-renderers-update-lock-update_lock).
- **`prepo::PlayReport::Send(Uid)`'s async context**: [An async context returned through x8](../../../docs/reference/services.md#an-async-context-returned-through-x8-prepoplayreportsend).
- **Float atomics as a compare-and-swap loop** (`EmitAtomicAddF32`) and **dead-code removal that keeps a multi-output producer's sources** (`Optimizer.RemoveNode`), both from the Mac host's fork: [Float atomics in storage memory](../../../docs/reference/shaders.md#float-atomics-in-storage-memory), [Dead-code removal dropped a coordinate of a multi-output instruction](../../../docs/reference/shaders.md#dead-code-removal-dropped-a-coordinate-of-a-multi-output-instruction).
- **Texture IDs read through the pool with lazy images** (`vka_spv_pool_mark`, early-test modules): [Texture IDs read through the pool with lazy images](../../../docs/reference/rendering.md#texture-ids-read-through-the-pool-with-lazy-images): the door and the unlit objects; GPU about 40 to 29 ms a frame in Link's house with the early tests kept.
- **Submission fences instead of the timeline semaphore on Android** (`vka_submit`, `completion_main`): [The completion thread's timeline wait made CPU and GPU take turns on Turnip](../../../docs/reference/frame-rate.md#the-completion-threads-timeline-wait-made-cpu-and-gpu-take-turns-on-turnip): Link's house from 18 to 21.7 fps on the AYN Thor; the GPU is the limit now.
- **Texture pool read marks in cached memory** (`pm_cached`): [Texture pool read marks read from uncached memory](../../../docs/reference/frame-rate.md#texture-pool-read-marks-read-from-uncached-memory): the replay's recording from 11.5 to 5.1 ms a frame with the change above.
- **Shuffles of emulated task and mesh programs through workgroup memory** (`DMSH_VK_MOD_MESH_EMU_SHUFFLE_LDS`): [Shuffles of task and mesh programs emulated as compute](../../../docs/reference/shaders.md#shuffles-of-task-and-mesh-programs-emulated-as-compute): the moss of Link's house, 18 → 3.5 ms of GPU a frame; Link's house from 21.7 to 31.2 fps on the AYN Thor.
- **GPU timestamps measured against the CPU clock** (`ts_calibrate`): [GPU times read with a wrong timestamp period](../../../docs/reference/frame-rate.md#gpu-times-read-with-a-wrong-timestamp-period): the Thor's Turnip says 33.11 ns a tick for 52.08; the game is GPU-bound in Link's house and outdoors.
- **Positions of mesh programs emulated as compute** (exact arithmetic for task and mesh programs on Android): [Positions of mesh programs emulated as compute](../../../docs/reference/shaders.md#positions-of-mesh-programs-emulated-as-compute): the door and foliage edges speckled white.
- **Query conditions on the Android Vulkan replay** (`rc_known`, from the Mac host): [Query conditions on the Android Vulkan replay](../../../docs/reference/rendering.md#query-conditions-on-the-android-vulkan-replay): objects white in flashes for about 20 s after a save loads.

- **F2IP's rounding modes** (`AF2ip`, from the Mac host's fork): [F2IP's rounding modes](../../../docs/reference/shaders.md#f2ips-rounding-modes): the leaves of Link's house white with a halo, only their depth pass drawn.
- **Pool windows: GPU-only pools' images laid out as the pool on Android**: [Render targets placed over one memory, each in an image of its own on the Vulkan replay](../../../docs/reference/rendering.md#render-targets-placed-over-one-memory-each-in-an-image-of-its-own-on-the-vulkan-replay).
